# 동사무소와 편지

공원 북쪽(월드 좌표 x=5, z=-20)에 동사무소를 배치했습니다. 앞의 부엉이 직원 **솔**에게 접근해 편지 버튼을 누르면 받은 편지, 보낸 편지, 편지 쓰기를 이용할 수 있습니다. 지도와 모리의 안내에도 동사무소가 표시됩니다.

## 배포 순서

기존 프로필·멀티플레이·팔로우 migration이 적용된 DB에서 다음 파일을 순서대로 실행한 뒤 프런트엔드를 배포합니다.

1. `supabase/migrations/202611160001_town_letters.sql`
2. `supabase/migrations/202611160002_expanded_park.sql`

이 작업에서 실제 운영 DB 적용은 수행하지 않았습니다. 새 클라이언트는 `town_action_expanded` RPC를 사용하므로 두 번째 migration을 먼저 적용해야 합니다. 기존 클라이언트와 기존 `town_action`은 그대로 동작합니다.

## 편지

- 내가 팔로우한 등록 완료 유저에게만 발송할 수 있습니다. 수신자의 맞팔은 필요하지 않습니다.
- 제목 80자, 본문 2,000자, 발신자당 24시간에 50통입니다.
- 발신자는 로그인 계정에서 결정합니다. 발신자·수신자만 편지 내용을 읽고, 읽음 처리는 수신자만 가능합니다.
- 전송 요청 ID로 중복 클릭과 같은 요청 재시도에 의한 중복 발송을 방지합니다.
- 편지는 DB에 저장되며 30통씩 페이지를 이동합니다. 팔로우를 해제해도 기존 편지는 남습니다. 계정 삭제 시 해당 계정의 송수신 편지는 삭제됩니다.
- DB 테이블 직접 접근은 차단하고 인증된 RPC만 허용합니다. 편지 본문은 HTML이 아닌 텍스트로 표시합니다.
- 데모에서는 실제 편지를 전송하지 않습니다.

## 확장 좌표

이동 범위는 x=100~1800, y=-200~1000입니다. 새 RPC는 기존 세션·활동·공연 처리와 잠금을 유지하며 기존 좌표 범위에는 호환 좌표를 전달합니다. 새 구역의 실제 좌표는 세션에 연결된 비공개 테이블에 저장하고, 기존 RPC가 허용한 참가자 목록에만 합성합니다. 만료·로그아웃 시 좌표도 삭제되며, 공연 및 서버 강제 이동은 확장 좌표보다 우선합니다.

배포 후 서로 다른 두 계정으로 팔로우 → 편지 전송 → 수신/읽음 처리, 제3자 접근 거부, 북쪽 구역의 서로 다른 브라우저 간 위치 동기화를 확인합니다.
