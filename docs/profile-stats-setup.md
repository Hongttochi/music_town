# 프로필 팬·활동 통계 적용

Supabase SQL Editor에서 `supabase/migrations/202611060002_profile_fans.sql` 전체를 한 번 실행한다. 기존 `member_profiles`, `town_sessions`, `town_performances`, `town_action(text,integer,integer,uuid,real,real)`가 있어야 한다. 운영 DB에는 아직 적용하지 않았다.

- `profile_fans`: 계정 간 팔로우·하트. 동일 계정 조합은 종류별 1건, 자기 자신에게 보내기 금지. 취소하면 집계에서 빠진다.
- `profile_daily_activity`: 한국 날짜별 접속·무대 시간. 프로필에는 누적 시간과 최근 7일 그래프를 표시한다.
- `profile_activity_cursor`: 중복 집계를 막는 마지막 정산 시각.
- `profile_fan_action`: 로그인한 사용자만 집계 조회·자신의 팔로우/하트 변경 가능. 다른 사람의 팬 명단이나 로그인 정보는 반환하지 않는다.
- `my_followed_profiles`: 요청한 계정 자신의 팔로우 목록만 반환한다.
- 기존 `town_action`은 `private.town_action_before_activity`로 옮겨 외부 호출을 차단한다. 새 공개 함수는 기존 기능을 호출하면서, 서버에서 확인한 세션·공연 시각으로만 시간을 누적한다. 기존 전역 트랜잭션 잠금을 그대로 사용한다. 배포 전 운영 함수가 위 시그니처와 기존 45초 세션 만료 정책을 사용하는지 확인한다.

시간은 공원 입장 후 서버가 확인한 구간을 집계한다. 단순 로그인 유지 시간은 포함하지 않는다. 무대 시간은 접속 시간에 포함된다. 끊긴 접속은 마지막 확인 시각으로부터 최대 45초까지만 인정하며, 마지막 구간은 후속 RPC에서 정산된다. 과거 기록을 복원하거나 클라이언트가 보낸 시간을 신뢰하지 않는다. 서버가 정리한 뒤 후속 정산이 없으면 마지막 짧은 구간이 누락될 수 있어 정밀 청구용 시간이 아니다.

기존 로컬 팔로우는 무대 번호만 보관했기 때문에 특정 계정으로 안전하게 이전할 수 없다. 새 기능부터 계정 기준으로 저장한다. SQL 미적용 또는 조회 실패 시 임의의 0 대신 오류와 재시도를 표시한다. 기능 활성화 이후부터 기록이 쌓인다.

검증: `node --test tests/profile-stats.test.mjs` (권한, 중복·자기 하트, 계정별 목록, 탈퇴 연쇄 삭제, 서버 시간, 만료 상한, 한국 자정 분리).
