# 법정대리인 동의·본인확인 설정

만 14세 미만 아동을 위한 **동의 표시 + 보호자 명의 휴대폰 본인확인** 절차다. PortOne V2에서 성인 보호자의 인증 결과를 서버가 조회한 후 가입·입장을 허용한다. 체크박스나 브라우저 반환 값만으로 승인하지 않는다.

## 현재 배포 상태와 활성화 조건

기본값은 비활성화다. 기존 서비스에 인증업체 미설정 상태의 차단 화면이 갑자기 노출되지 않도록 `VITE_GUARDIAN_CONSENT_ENABLED`와 `GUARDIAN_CONSENT_ENABLED` 두 설정을 명시적으로 켠다. **비활성화 상태는 보호자 동의 절차가 운영 중이라는 뜻이 아니다.** 실제 아동 가입 지원 전에 아래 절차를 완료해야 한다.

1. PortOne에서 휴대폰 본인확인 계약을 체결하고 사용할 **실거래(LIVE) 본인인증 채널**을 연결한다. 결제 전용 채널이나 테스트 결과로 아동의 가입을 승인하지 않는다.
2. PortOne에서 반환하는 인증 결과에 보호자 성명, 생년월일, 전화번호와 채널 정보가 포함되는지 확인한다. 이 중 필요한 정보가 없으면 승인하지 않는다.
3. 기존 `member_profiles`, 멀티플레이 `town_action`이 설치된 운영 DB에 `supabase/migrations/202611060001_guardian_consent.sql`을 **한 번** 실행한다. 기존 RPC를 private 스키마로 이동해 감싸므로, 운영 중인 함수 본문·기존 RLS 정책과 호환되는지 스테이징에서 먼저 검증한다. 이 저장소에 기존 SQL 파일은 없으므로 운영자가 적용한 원본과 대조해야 한다.
4. 아래 서버 환경변수를 Vercel에 설정하고 두 활성화 플래그를 켜서 재배포한다. DB 강제 제한과 프런트 활성화는 점검 시간에 함께 적용한다. **SQL만 적용하면 기존 계정도 동의 확인 전 공원·프로필 접근이 제한된다.** 반대로 화면만 켜고 SQL을 적용하지 않으면 DB 우회 방어가 완성되지 않는다.
5. 아동·보호자 정보의 보유·파기 기준과 연동된 인증업체의 처리·위탁 조건을 확정하고, 실제 계약 및 운영 설정을 개인정보처리방침과 동의 문서에 반영한다. 현재 문서는 검토본이다. 새 문구로 받을 때는 아래 버전 갱신 절차도 따른다.
6. 실제 보호자 명의 테스트로 모바일 인증 → 복귀 → 아동 계정 연결 → DB 접근을 확인한다. 개발 검증에서는 실제 본인인증·문자 발송·운영 DB 변경을 수행하지 않았다.

| 환경변수                                            | 값·용도                                                                                                                      |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `VITE_GUARDIAN_CONSENT_ENABLED`                     | `true`: 브라우저 연령·동의 화면 활성화. 빌드 시 적용                                                                         |
| `GUARDIAN_CONSENT_ENABLED`                          | `true`: 서버 API 활성화                                                                                                      |
| `APP_ORIGIN`                                        | 실제 HTTPS 서비스 origin. 예: `https://music-town-hb2j.vercel.app`. 경로와 마지막 `/` 없이 지정                              |
| `SUPABASE_URL` / `VITE_SUPABASE_URL`                | Supabase 프로젝트 URL                                                                                                        |
| `SUPABASE_SECRET_KEY` / `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 키. DB 기록 및 검증된 본인 계정 연결에 사용                                                                        |
| `ADMISSION_HASH_SECRET`                             | 무작위 서버 전용 문자열, 최소 32자. 전화번호·접속 제한 키의 HMAC에 사용. 변경 시 기존 동의 확인 기록의 식별 해시 관리도 검토 |
| `PORTONE_STORE_ID`                                  | 실제 본인확인 상점 ID                                                                                                        |
| `PORTONE_CHANNEL_KEY`                               | LIVE 본인인증 채널 키                                                                                                        |
| `PORTONE_API_SECRET`                                | 서버 전용 PortOne V2 API 시크릿                                                                                              |

서버 키에는 `VITE_` 접두사를 붙이지 않는다. 플래그는 동의 증명이 아니며, DB가 활성화된 뒤 브라우저 플래그를 지우더라도 서버 입장 제한은 해제되지 않는다. 이 API는 Vercel의 신뢰 가능한 접속 IP 헤더를 전제로 DB에서 시간당 요청 수를 제한한다. 다른 호스팅으로 옮기면 신뢰할 프록시 헤더를 함께 검토한다.

## 흐름과 저장 정보

- 정상 앱 흐름에서는 최초 소셜 로그인 **전** 생년월일로 만 14세 미만 여부를 서버에서 분류한다. 생년월일 원문은 DB에 저장하지 않는다. 이 연령 구분은 이용자의 신고에 의존하며 연령 자체의 본인인증은 아니다. 허위 연령 입력을 완전히 판별하는 기능으로 안내해서는 안 된다.
- Supabase Auth의 공개 OAuth 엔드포인트 자체를 대체하거나 신규 Auth 계정 생성을 제한하는 훅은 추가하지 않는다. 직접 OAuth 요청으로 인증 계정이 만들어지더라도 DB의 프로필·공원 이용 검증은 별도로 적용된다. Auth 계층의 계정 생성 자체까지 동의에 연동해야 하는 운영 요건은 활성화 전에 별도 설계·검토한다.
- 만 14세 미만이면 보호자가 동일 화면에서 동의 내용·버전별 약관과 방침을 읽고, 법정대리인임과 관계·필수 동의를 표시한다. 보호자는 본인 명의 휴대폰 인증을 진행한다. 가족관계 서류를 조회하거나 부모·자녀 관계를 자동 증명하는 기능은 아니다.
- 요청마다 서버가 본인확인 거래번호를 생성한다. 브라우저의 `approved`·계정 ID·인증 결과·다른 거래번호는 승인 근거로 사용하지 않는다.
- PortOne 서버의 `VERIFIED`, LIVE 채널, 지정 채널·거래번호, 인증 시각, 만 19세 이상 여부를 확인한다. 미성년자·취소·테스트·불일치·만료·조회 실패는 승인하지 않는다.
- 승인 전 요청은 1시간 유효한 HttpOnly·Secure·SameSite 쿠키로 브라우저에 묶인다. 쿠키에는 무작위 값만 있고 DB에는 해당 값의 해시를 둔다. 발급 시 클라이언트에 원문 토큰을 JSON으로 반환하지 않는다.
- 확인 후 OAuth로 로그인하면 서버가 검증한 계정 ID에 동의를 원자적으로 연결한다. 하나의 요청을 다른 계정에 재사용할 수 없다. 기존 로그인 계정도 미동의 상태라면 절차를 거친다.
- 기록은 `service_admission_requests`와 `member_admissions`에 저장한다. 동의 시각·관계·문서 버전·본문 및 문서 해시·본인확인 거래번호·보호자 성명·성인 확인 결과·전화번호의 HMAC을 남긴다. 주민등록번호·CI 원문·보호자 전체 생년월일·전화번호 원문은 서비스 DB에 저장하지 않는다. 인증업체 자체 처리에는 별도 계약과 정책이 적용된다.
- 브라우저 계정은 두 테이블을 직접 읽거나 변경할 수 없다. 원본 프로필 소유자 정책에 추가한 restrictive 정책과 public `town_action`의 검증이 미동의 이용을 막는다. 음성 토큰도 기존 서버의 town snapshot 검증을 거치므로 공원 입장 제한에 연동된다. 표준 시그니처의 `submit_town_report(uuid,uuid,text,text)`가 설치되어 있으면 신고 RPC에도 같은 검증을 추가한다. 다른 시그니처나 별도 쓰기 API가 있으면 활성화 전에 해당 경로도 점검해야 한다.
- 익명 미완료 요청은 만료 후 1일이 경과하면 다음 예약 요청에서 정리한다. 별도의 예약 파기 작업은 아니므로 정확히 하루 뒤 물리 삭제를 보장하지 않는다. 계정에 연결된 증빙은 계정 삭제에 연동한다. 연동된 미동의 계정의 연령 구분은 쿠키 삭제를 통한 재신고 우회를 막기 위해 계정에 남는다.

## 철회와 운영자 처리

법정대리인의 철회 요청은 문의처로 접수하고 적절한 본인·대리권 확인 후 운영자가 아래 서버 전용 함수를 실행한다. 브라우저 역할에는 실행 권한이 없다.

```sql
select public.revoke_service_admission('대상 사용자 UUID');
```

계정의 동의를 철회하고 공원 세션을 정리한다. 이후 RPC와 프로필 접근은 즉시 제한되며 화면은 다음 동의 상태 확인(최대 60초 또는 재접속)에 따라 잠긴다. 기존 음성 연결·이미 발급된 토큰의 처리 범위는 음성 서비스 설정과 함께 운영 검증한다. 과거 승인 쿠키만으로 철회를 취소할 수 없고, 새 요청·동의가 필요하다. 문의를 받았다는 사실만으로 무조건 철회하거나 다른 계정의 동의를 변경하지 않는다.

## 동의 문서 버전

- 현재 버전: `2026-11-06-v1`.
- `public/consent/<버전>/terms.html`, `privacy.html`은 해당 버전 원문이다. 운영 중인 버전의 원문을 덮어쓰지 않는다.
- `server/admission-policy.mjs`는 동의 문구와 원문 URL·SHA-256을 보유한다. 서버는 본문과 문서 해시를 함께 기록하며 브라우저의 버전을 검사한다.
- 내용이 바뀌면 새 버전 디렉터리와 해시를 만들고, 서버·화면의 버전 및 DB `private.has_service_admission`의 허용 버전을 함께 갱신한다. 필요한 재동의가 끝나기 전 새 버전으로 조용히 승인하지 않는다.

## 검증

```sh
node --test tests/*.test.mjs
VITE_GUARDIAN_CONSENT_ENABLED=true npm run build
```

API 위조·성인 여부·만료·샌드박스 결과·재사용, 실제 로컬 PostgreSQL 엔진에서 권한/RLS/철회/계정 삭제 및 전역 요청 제한을 검증한다. 브라우저에서는 가로·세로 연령 화면, 필수 동의, 공급자 실패·취소 시 차단, 승인 복귀 흐름을 모의 API로 확인했다. 실사용 인증업체 연결과 운영 DB 적용을 대신하는 테스트는 아니다.
